# -----------------------------------------------------------------------------
# WHY these --add-opens flags are mandatory on Java 17:
# Spark's Tungsten memory manager, Kryo serializer, and closure-cleaning
# reflection utilities access internal JDK fields directly. Java 9+'s
# module system (JPMS) strong encapsulation blocks this by default, causing
# `InaccessibleObjectException` at runtime. Spark 3.x officially requires
# these exact --add-opens flags for Java 17 support (see Spark docs:
# "Running Spark on Java 17"). Without them, local[*] execution fails
# immediately during SparkSession.builder().getOrCreate().
# -----------------------------------------------------------------------------
